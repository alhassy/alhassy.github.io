1. Typical workflow How do I publish an article

  1. Open an Org-mode buffer —or call blog-new-article (or blog-new-post).
  2. Invoke my/blogging-mode to get live WYSIWYG in an adjacent buffer after every save C-x C-s.
    • The mode is auto-enabled in ~/blog/ via .dir-locals.el.

  3. Until content:

    1. ✏️ Write, write, and write!
      • E.g., insert an image with C-c i i (from file) or C-c i s (screenshot)
    2. 👀 C-x C-s to save & preview

    🤔 Consider using C-x n s, or C-x n n, to focus your attention on a particular section, thereby dramatically increasing the speed at which the preview renders. 💥

  4. 🤖 git push when you're done —CI runs blog-publish-all and deploys public/ to gh-pages, index, RSS, and tag pages included.
    • Changes go live about 2 minutes after the push; see §Deployment via CI.

1.1. Why not use an existing blogging platform?

I dislike coding in any website's primitive textarea, likewise for general writing.

For a brief period, I used Hashnode: I'd write in Emacs, then C-c C-e C-b h h to export current body as HTML, then paste that into Hashnode. However, Hashnode does not respect my CSS nor my inline JS. This was problematic, since I wanted to write a tiny root-meaning program to learn Arabic and to have a tiny web-app for Arabic shows for my kids.

2. Seamlessly Previewing Articles within Emacs 😲

Every save, C-x C-s, shows the final product —image, abstract, header, footer, and all styles— in a JavaScript-capable browser within Emacs; ≈WYSIWYG≈.

The pieces:

  • blog:header and blog:footer —Org links that give any Org file the blog's CSS/JS stack.
  • The blog export backend —wraps each article in header, tags, image, badges, and footer.
  • C-x C-s, under my/blogging-mode —export with blog and show the result in an xwidget to the right; for a multiple-article file, just the heading at point. Outside ~/blog/, blog-preview does the same.
  • Badges and footer —Source and History badges under the article image, since nobody scrolls to the bottom; the license and ReadRemaining.js clock at the end.

2.1. org-link/blog: Using My Blog Styles Anywhere

Details

Any Org file, blog or not, gets our styling from the Org links blog:header and blog:footer; they adapt the examples in org-deflink's docstring. Outside ~/blog/, CSS and JS load from alhassy.com/resources/ —so we need internet— and the History badge dangles. 

(org-deflink blog
  "Provide the styles for 'www.alhassy.com's header and footer.

The use of 'blog:footer' aims to provide a clickable list of tags and an HTMLized version of the Org source.
For details, consult the blog--footer function.

Finally, I want to avoid any `@@backend:...@@' from appearing in the browser frame's title.
We accomplish this with the help of some handy-dandy JavaScript: Just use 'blog:sanitise-title'.
"
      (pcase o-label
        ("header" (blog--header-html (blog--info (buffer-file-name))))
        ("footer" (blog--footer (buffer-file-name)))
        ("sanitise-title" blog--sanitise-title-js)
        (_ "")))

(defconst blog--sanitise-title-js
  "<script> window.parent.document.title =  window.parent.document.title.replace(/@@.*@@/, \"\") </script>"
  "Strip any `@@backend:...@@' from the browser frame's title.")

(defun blog--header-html (post)
  "POST ↦ the site nav, CSS/JS stack, and fancy title that open every article."
  (concat
   blog-page-preamble

   "<link href=\"https://alhassy.github.io/floating-toc.css\" rel=\"stylesheet\" type=\"text/css\" />"

   (format "<br><center><h1 class=\"post-title\">%s</h1></center>" (blog--title-html (@title post)))))

2.2. The blog export backend: header, tags, image, badges, and footer

Details

Every article is exported with blog, a backend derived from html that overrides two things:

  • :options-alist —a 2-level TOC, no drawers, no Org title nor postamble, captions below tables, and clickable headlines; an article's own #+options: still win.
  • inner-template —header, tags, image, and badges; then Org's usual body; then the footer.

Its parent, blog-page, exports the index and tag pages with just the §stable anchors, so no random orgXXXXXXX id appears anywhere on the site. Nothing is global: C-c C-e h h on an unrelated Org file is untouched. 

;; Every page on the site ---index and tag pages included--- gets stable, human-named anchors.
(org-export-define-derived-backend 'blog-page 'html
  :options-alist '((:html-prefer-user-labels nil nil t))
  :filters-alist '((:filter-parse-tree . blog--stable-headline-ids)
                   (:filter-final-output . blog--no-random-ids)))

;; Articles additionally get the blog look.
(org-export-define-derived-backend 'blog 'blog-page
  :options-alist '((:with-toc nil "toc" 2)
                   (:with-drawers nil "d" nil)
                   (:with-title nil "title" nil)
                   (:html-postamble nil "html-postamble" nil)
                   (:html-table-caption-above nil nil nil)
                   (:html-format-headline-function nil nil #'blog--format-headline))
  :translate-alist '((headline . blog--headline)
                     (link . blog--link)
                     (inner-template . blog--inner-template)))

(defvar blog--link-base-directory nil
  "Directory that relative file links resolve against; nil means the exported file's own directory.

`blog--publish-single-subtree' binds it to the container's directory, since it exports a temp copy.")

(defun blog--link (link desc info)
  "Org's HTML for LINK, a relative file path re-rooted at `blog-posts-directory'; the site is flat.

By way of example, in =emacs/foo.org=, =[[file:../resources/x.png]]= ↦ =resources/x.png= and
=[[file:../life/bar.org]]= ↦ =bar.html=, since every page is served from the root.  Files outside
the blog keep their links as written.  Radio links point at their =<<<target>>>='s label, not a random id."
  (let ((root (file-name-as-directory (expand-file-name blog-posts-directory)))
        (base (or blog--link-base-directory
                  (file-name-directory (or (plist-get info :input-file) default-directory))))
        (path (org-element-property :path link)))
    (when (and (equal (org-element-property :type link) "file")
               (not (file-name-absolute-p path))
               (file-in-directory-p base root))
      (let ((target (expand-file-name path base)))
        ;; Another article is a sibling on the flat site, wherever its source lives.
        (org-element-put-property link :path (if (equal (file-name-extension target) "org")
                                                 (file-name-nondirectory target)
                                               (file-relative-name target root)))))
    ;; Org's own radio links use a random id, while their <<<target>>> uses its label; agree on the label.
    (if-let ((radio (and (equal (org-element-property :type link) "radio")
                         (org-export-resolve-radio-link link info))))
        (format "<a href=\"#%s\">%s</a>" (org-html--reference radio info) desc)
      (org-html-link link desc info))))

(defun blog--inner-template (contents info)
  "(CONTENTS, INFO) ↦ header ⊕ tags ⊕ image ⊕ badges ⊕ Org's own body (TOC titled Ξ) ⊕ footer."
  (let* ((file (plist-get info :input-file))
         (post (blog--info file)))
    (concat
     (blog--header-html post)
     blog--sanitise-title-js
     "<center>" (@tags post) "</center>"
     (@image post (blog--url "resources/"))
     (blog--badges-bar post file)
     (replace-regexp-in-string "<h\\([0-9]\\)>Table of Contents</h\\1>"
                               (lambda (h) (s-replace "Table of Contents" (blog--toc-title) h))
                               (org-html-inner-template contents info) t t)
     (blog--footer file))))

(defun blog--stable-headline-ids (tree _backend info)
  "Give each headline lacking a :CUSTOM_ID: the slug `blog--ensure-useful-section-anchors' would stamp.

That function only runs on C-x C-s; here we cover files not re-saved since, so
CI never falls back to Org's random `orgXXXXXXX' anchors.  Collisions get -2, -3, …"
  (let* ((headlines (org-element-map tree 'headline #'identity info))
         (taken (delq nil (mapcar (lambda (h) (org-element-property :CUSTOM_ID h)) headlines))))
    (dolist (h headlines tree)
      (unless (org-element-property :CUSTOM_ID h)
        (let* ((base (blog--make-slug (org-element-property :raw-value h)))
               (base (if (string-empty-p base) "section" base))
               (slug base)
               (n 1))
          (while (member slug taken) (setq slug (format "%s-%d" base (cl-incf n))))
          (push slug taken)
          (org-element-put-property h :CUSTOM_ID slug))))))

(defun blog--no-random-ids (html _backend _info)
  "HTML ↦ HTML sans Org's random `orgXXXXXXX' ids; signal, with a suggested name, when a link targets one.

Headlines, `<<targets>>' and `#+name:'d elements all get stable ids, so a random
id is only ever on something nobody can link to ---unless a link does, which we
refuse to publish: its URL would change on every export."
  (let ((case-fold-search nil))
    (when (string-match "<a href=\"#org[0-9a-f]\\{7\\}\"[^>]*>\\(.*?\\)</a>" html)
      (let ((text (replace-regexp-in-string "<[^>]*>" "" (match-string 1 html))))
        (user-error "Link “%s” targets an element Org can only give a random id; name it, e.g. #+name: %s"
                    text (blog--make-slug text))))
    (replace-regexp-in-string " id=\"org[0-9a-f]\\{7\\}\"" "" html t t)))

(defvar blog--current-headline nil
  "The headline `blog--headline' is transcoding; read by `blog--format-headline'.")

(defun blog--headline (headline contents info)
  "Transcode HEADLINE as `org-html-headline' does, exposing it to `blog--format-headline'."
  (let ((blog--current-headline headline))
    (org-html-headline headline contents info)))

(defun blog--style-setup (backend)
  "Wrap the “* Abstract” section in an abstract block, for =blog= exports only.

(The abstract is an ordinary section in the source, so this is the one thing that
must happen before parsing; everything else lives in the =blog= backend.)"
  (when (org-export-derived-backend-p backend 'blog)
    (goto-char (point-min))
    ;; Previewing a narrowed subtree: links to the rest of the file are expected to dangle.
    (when (buffer-narrowed-p) (insert "#+options: broken-links:t\n"))
    (when-let ((bounds (blog--abstract-bounds)))
      (goto-char (cdr bounds))
      (insert "\n#+end_abstract\n")
      (goto-char (car bounds))
      (insert "\n#+begin_abstract\n"))))

(defun blog--abstract-bounds ()
  "Current buffer ↦ (BEG . END) of the “* Abstract” section's body, past any :PROPERTIES: drawer; nil if absent.

A top-level section ends at the next top-level heading, so plain regex suffices ---no `org-mode' needed."
  (save-excursion
    (goto-char (point-min))
    (when (re-search-forward "^\\* Abstract" nil t)
      (forward-line)
      (when (looking-at-p "^[ \t]*:PROPERTIES:")
        (re-search-forward "^[ \t]*:END:" nil t)
        (forward-line))
      (cons (point)
            (if (re-search-forward "^\\* " nil t) (match-beginning 0) (point-max))))))

(add-hook 'org-export-before-processing-hook #'blog--style-setup)

2.3. Inserting org-link/blog <em>seamlessly</em> via the export process; <em>then</em> preview with every save

Details

Previews open in an xwidget-webkit buffer, so Emacs must be built with xwidgets; on macOS: 

brew reinstall emacs-plus@30 --with-xwidgets --with-imagemagick --with-dbus --with-debug

Confirm support is present with: (featurep 'xwidget-internal). 

(defun blog--xwidget-buffers ()
  "Return the list of live buffers whose major mode is xwidget-webkit-mode."
  (seq-filter (lambda (b)
                (eq 'xwidget-webkit-mode (buffer-local-value 'major-mode b)))
              (buffer-list)))

(defun blog--show-preview (url)
  "Display URL in an xwidget buffer to the right of the current Org window.

Guarantees [Org source | xwidget] side-by-side layout:
- If there is already an xwidget window on the right, reuse it.
- Otherwise split the current window to the right and open there.
- The Org source window is never taken over."
  (delete-other-windows)  
  (let* ((org-win   (selected-window))
         (xw-buf    (car (blog--xwidget-buffers)))
         (xw-win    (and xw-buf (get-buffer-window xw-buf))))
    (if (and xw-win (not (eq xw-win org-win)))
        ;; Reuse the existing xwidget window ---just navigate.
        (progn
          (select-window xw-win)
          (xwidget-webkit-browse-url url)
          (select-window org-win))
      ;; No usable xwidget window ---split right and open there.
      (let ((right-win (split-window org-win nil 'right)))
        (select-window right-win)
        (xwidget-webkit-browse-url url)
        (select-window org-win)))))

(defun blog--preview-standalone ()
  "Export the current standalone Org buffer to HTML and open it in xwidget.

Called from the buffer-local after-save-hook installed by blog-preview.
Mirrors blog-preview-subtree but for files without #+article_style: multiple."
  ;; Under the blog, write to its root ---as CI does--- so a nested file's re-rooted links resolve.
  (let* ((root (expand-file-name blog-posts-directory))
         (html (if (file-in-directory-p buffer-file-name root)
                   (expand-file-name (concat (f-base buffer-file-name) ".html") root)
                 (concat (file-name-sans-extension buffer-file-name) ".html"))))
    (message "=> Previewing standalone %s..." (buffer-name))
    (org-export-to-file 'blog html)
    (when (file-exists-p html)
      (blog--show-preview (concat "file://" html)))))

(cl-defun blog-preview ()
  "Render the current Org buffer with full blog styling in an xwidget window.

Installs a buffer-local after-save-hook so that every subsequent C-x C-s
re-exports and refreshes the preview automatically.

This is the entry point for previewing *any* Org file with blog styling ---not
just files under ~/blog.  On a file outside the blog repo all CSS and JS are
loaded from absolute https://alhassy.com/resources/ URLs (internet required),
metadata keywords fall back to sensible defaults (default image, empty tags,
generic description), and the history badge links to a GitHub URL that won't
resolve.  Everything visual still works.

In ~/blog files, prefer my/blogging-mode (C-x C-s there runs the full
preprocessing pipeline: slug assignment, modified-stamp, validation, then
preview).  blog-preview is a no-op when my/blogging-mode is already active ---
that mode owns the save+preview cycle directly."
  (interactive)
  (when (bound-and-true-p my/blogging-mode)
    (message "blog-preview: my/blogging-mode is active; C-x C-s handles preview.")
    (cl-return-from blog-preview))
  ;; Kill any stale org-preview-html-mode ---it puts org-preview-html-refresh on
  ;; after-save-hook, and that errors when --html-file is nil (our path never sets it).
  (when (bound-and-true-p org-preview-html-mode)
    (org-preview-html-mode -1))
  (remove-hook 'after-save-hook #'org-preview-html-refresh t)
  ;; Ensure no xwidget buffer lingers ---otherwise Emacs might hang on re-preview.
  (let ((kill-buffer-query-functions nil))
    (mapc #'kill-buffer (blog--xwidget-buffers)))
  (if (blog--multiple-style-p)
      ;; Multiple-style: preview heading at point on every save (buffer-local hook).
      (add-hook 'after-save-hook #'blog-preview-subtree nil t)
    ;; Standalone: bypass org-preview-html-mode (file:// download bug on macOS).
    (add-hook 'after-save-hook #'blog--preview-standalone nil t)
    (blog--preview-standalone)))

(defun blog-preview-subtree ()
  "Preview the top-level heading at point as a standalone blog article.

For use in multiple-style (#+article_style: multiple) files.
Called automatically by the buffer-local after-save-hook set up by blog-preview.

Opens (or reuses) an xwidget window to the right of the Org source buffer,
maintaining a stable [Org source | xwidget] side-by-side layout."
  (interactive)
  (let ((kill-buffer-query-functions nil))
    (unless (blog--multiple-style-p)
      (user-error "Not a multiple-style file; use blog-preview instead"))
    ;; Navigate to enclosing top-level heading.
    (save-excursion
      (unless (org-at-heading-p) (outline-previous-heading))
      (while (> (org-outline-level) 1) (org-up-heading-safe))
      (let* ((tags  (mapcar #'downcase (org-get-tags)))
             (_ (when (member "noexport" tags)
                  (user-error "Heading is tagged :noexport: ---nothing to preview")))
             (_ (when (org-element-property :commentedp (org-element-at-point))
                  (user-error "Heading is COMMENT ---nothing to preview")))
             (title     (org-get-heading t t t t))
             (slug      (or (org-entry-get (point) "CUSTOM_ID")
                            (blog--make-slug (or (org-entry-get (point) "TITLE") title))))
             (all-infos (blog--info-multiple (buffer-file-name)))
             (info      (blog--find-info-by-slug slug all-infos))
             (html-out  (expand-file-name (concat slug ".html") blog-publish-directory)))
        (message "=> Previewing %s..." title)
        (blog--publish-single-subtree (point) (buffer-file-name) info)
        (when (file-exists-p html-out)
          ;; blog--show-preview reuses the existing xwidget window when present,
          ;; so the [Org | xwidget] split is stable across repeated saves.
          (blog--show-preview (concat "file://" (expand-file-name html-out))))))))

On each C-x C-s, a standalone foo.org exports beside itself as foo.html, and a container heading to public/<slug>.html. Narrowing, C-x n s, keeps this fast.

2.5. blog–htmlize-file: Generate an htmlized version of a given source file; return an HTML badge linking to the colourised file

Details

Each .org.html page is htmlize's inline-css rendering: the file as Emacs shows it, with the tsdh-light colours loaded atop AlBasmala.el baked into the spans. 

(defun blog--source-badge (url)
  "URL ↦ the “Source” badge linking to an article's colourised Org source."
  (concat "<a class=\"tooltip\" title=\"See the colourised Org source of this article; i.e., what I typed to get this nice webpage\" href=\""
          url "\"><img src=\"https://img.shields.io/badge/-Source-informational?logo=read-the-docs\"></a>"))

(defun blog--htmlize-to (name)
  "Write the current Org buffer, fully unfolded and htmlized with inline CSS, to `blog-publish-directory'/NAME.org.html.

The <title> is the buffer's file name, so callers let-bind `buffer-file-name'."
  (let ((htmlize-output-type 'inline-css)
        (inhibit-message t))
    (outline-show-all)
    (with-current-buffer (htmlize-buffer)
      (write-file (expand-file-name (concat name ".org.html") blog-publish-directory))
      (kill-buffer))))

(defun blog--htmlize-file (file-name)
  "FILE-NAME ↦ the Source badge for it, having written its colourised source to public/BASE.org.html."
  (let ((org-hide-block-startup nil))
    (with-temp-buffer
      ;; Not `find-file': that hands back the live editing buffer, and re-running
      ;; `org-mode' there resets its local state and re-fires .dir-locals.el.
      (insert-file-contents file-name)
      (org-mode)
      (let ((buffer-file-name file-name))
        (blog--htmlize-to (f-base file-name)))))
  (blog--source-badge (concat (f-base file-name) ".org.html")))

(defun blog--license ()
  "Get HTML for Creative Commons Attribution-ShareAlike 3.0 Unported License."

2.8.1. The Two Article Styles: standalone vs multiple

We support two ways to author blog posts, selectable per-file via #+article_style:.

  1. standalone (the default)

    One .org file = one article; its file-level keywords (#+title:, #+filetags:, …) supply the metadata.

  2. multiple (container files)

    One .org file = N articles, one per top-level heading. Starting a post is then just C-RET, a few prompts, and writing —no new file, slug, or keywords.

    A container file looks like this: 

    #+title: My Life Posts
#+article_style: multiple

* A Walk in the Park                       :life:
:PROPERTIES:
:DATE:        <2026-05-03>
:DESCRIPTION: An evening walk with the kids.
:IMAGE:       park.png 350 350
:END:

** Abstract :ignore:
An evening walk with the kids ---the light was perfect.

** The Walk
...

* Quick Emacs Tip: visual-line-mode        :emacs:draft:
:PROPERTIES:
:DATE:        <2026-05-04>
:DESCRIPTION: One line, no scroll bar.
:CUSTOM_ID:   quick-emacs-tip-visual-line-mode
:END:
...

* Private scratch                          :noexport:
...

    Key rules:

    • Heading tags → article tags, sans structural ones (noexport, draft, ignore, details, …).
    • :draft: → a draft; blog-new-post adds it, and we axe it when ready.
    • :noexport: or COMMENT → skipped entirely; never exported or indexed.
    • :TITLE: → the display title and slug source, overriding a decorated heading.
    • :CUSTOM_ID: → the URL slug; see §slugs.
    • Abstract → :ABSTRACT:, else the ** Abstract :ignore: child, else the first paragraph.
  3. How the export pipeline connects the two styles

    The blog backend reads an article's metadata from file-level #+keyword: lines, via blog--info; a container heading keeps its metadata in a :PROPERTIES: drawer instead. So blog--publish-single-subtree turns the heading into a synthetic temp file:

    1. blog--info-subtree reads the heading's metadata.
    2. The temp file gets the matching file-level keywords ---#+title:, #+filetags:, #+fileimage:, #+description:— plus #+history_url: and #+htmlized_source_url:, pointing the badges at the container's git log and the per-article colourised source.
    3. The subtree body is pasted in and promoted a level; e.g., ** Abstract :ignore: ↦ * Abstract :ignore:, just where blog--style-setup looks for it.
    4. We export with the blog backend, as for any standalone post.
    5. A narrowed copy of the subtree is htmlized into <slug>.org.html.

    Both styles thus share one export pipeline; they differ only in how they reach it.

  4. Slug derivation, write-back, and global uniqueness

    By way of example, the heading * Quick Emacs Tip: visual-line-mode is published at alhassy.com/quick-emacs-tip-visual-line-mode.

    • A container heading's slug is its :CUSTOM_ID:; C-x C-s stamps a missing one with blog--make-slug of the title, so later title edits never shift the URL.
    • blog--validate-slugs refuses a slug that isn't lower-case kebab-case, or that another article —container or standalone— already owns, naming both.

    Each heading is then just another post-alist, so blog-make-index-page needs no special case.

    Org exports #+description as HTML metadata, so a link pasted into social media unfurls into a card with its image, description, and author. We keep it a terse one-liner; the longer story goes in the Abstract heading.

    Below we make new articles and read their metadata into post-alists.

(defun blog--info (post-filename)
  "Extract the `#+BLOG_KEYWORD: VALUE` pairs from POST-FILENAME.

Example use: (blog--info \"~/blog/HeytingAlgebra.org\")

For container sub-articles, the temp file may carry synthetic keywords:
  #+history_url:         ---overrides the auto-computed GitHub history URL
  #+htmlized_source_url: ---URL for the per-article colourised source badge
These are ignored for ordinary standalone files (regex yields nil, fallback applies)."
  (let ((case-fold-search t))
    (with-temp-buffer
      (insert-file-contents post-filename)
      (let* ((keyword-pairs
              (cl-loop for (prop.name prop.regex prop.default) on
                    `("title"                "^\\#\\+title:[ ]*\\(.+\\)$"                ,post-filename
                      "date"                 "^\\#\\+modified:[ ]*\\([0-9][-0-9 a-zA-Z:]+\\)$" ,(format-time-string "%Y-%m-%d")
                      "image"                "^\\#\\+fileimage: \\(.*\\)"                "emacs-birthday-present.png 350 350"
                      "description"          "^\\#\\+description:[ ]*\\(.+\\)$"          "I learned something neat, and wanted to share!"
                      "tags"                 "^\\#\\+filetags:[ ]*\\(.+\\)$"             "" ;; String; Space-separated
                      "history_url"          "^\\#\\+history_url:[ ]*\\(.+\\)$"          nil
                      "htmlized_source_url"  "^\\#\\+htmlized_source_url:[ ]*\\(.+\\)$"  nil
                      "site_nav"             "^\\#\\+site_nav:[ ]*\\(.+\\)$"             nil
                      "modified"             "^\\#\\+modified:[ ]*\\(.+\\)$"             nil
                      )
                  by 'cdddr
                  ;; See: https://stackoverflow.com/questions/19774603/convert-alist-to-from-regular-list-in-elisp
                  do (goto-char (point-min))
                  collect (cons prop.name
                                (if (search-forward-regexp prop.regex nil t)
                                    (match-string 1)
                                  prop.default)))))
        (-snoc
         (cons
          (cons "file" (f-base post-filename))
          keyword-pairs)
         (cons "url" (blog--url (f-base post-filename)))
         ;; Prefer an explicit #+history_url: (injected for container sub-articles)
         ;; over the auto-derived URL based on the file basename.
         (cons "history"
               (or (cdr (assoc "history_url" keyword-pairs))
                   (blog--history-url post-filename)))
         (cons "abstract" (when-let ((bounds (blog--abstract-bounds)))
                            (buffer-substring-no-properties (car bounds) (cdr bounds)))))))))

(defun blog--make-slug (title)
  "Convert TITLE to a URL-safe kebab-case slug.

2.8.11. blog–info-subtree, blog–info-multiple: Extract metadata from container headings

Details

The multiple-style analogues of blog--info: blog--info-subtree reads a heading's drawer and tags via org-element. blog--info-multiple parses the container once —per-heading parses would be quadratic— and yields one alist per publishable heading, with blog--info's keys plus "slug" and "container". 

(defun blog--info-subtree-abstract (headline-node)
  "Return the abstract text for HEADLINE-NODE, or nil.

Priority:
1. :ABSTRACT: property on the headline.
2. A child heading whose title matches /abstract/i (e.g. ** Abstract :ignore:).
3. The first paragraph element in the heading body."
  (or
   ;; 1. Explicit property
   (org-element-property :ABSTRACT headline-node)
   ;; 2. Child heading named Abstract
   (org-element-map headline-node 'headline
     (lambda (child)
       (when (and (= (org-element-property :level child)
                    (1+ (org-element-property :level headline-node)))
                  (string-match-p "abstract"
                                  (downcase (or (org-element-property :raw-value child) ""))))
         (org-element-interpret-data (org-element-contents child))))
     nil t)
   ;; 3. First paragraph fallback
   (org-element-map headline-node 'paragraph
     (lambda (para) (org-element-interpret-data para))
     nil t)))

(defun blog--info-subtree (headline-node container-file slug)
  "Extract post metadata for HEADLINE-NODE from CONTAINER-FILE with SLUG.

Returns nil when the headline carries a :noexport: tag or the COMMENT keyword.
Returns an alist with the same keys as blog--info plus \"slug\" and \"container\"."
  (let* ((heading-tags (mapcar #'downcase
                               (org-element-property :tags headline-node))))
    (unless (or (member "noexport" heading-tags)
                (org-element-property :commentedp headline-node))
      (let* (;; draft?
             (draft? (or (member "draft" heading-tags)
                         (equal "t" (org-element-property :DRAFT headline-node))))
             ;; title: :TITLE: property overrides heading text
             (title (or (org-element-property :TITLE headline-node)
                        (org-element-property :raw-value headline-node)))
             ;; date ---prefer :MODIFIED:, fall back to :DATE: for old articles
             (date-raw (or (org-element-property :MODIFIED headline-node)
                           (org-element-property :DATE headline-node)))
             (date (if date-raw
                       (replace-regexp-in-string "[<>]" "" date-raw)
                     (format-time-string "%Y-%m-%d")))
             ;; description
             (description (or (org-element-property :DESCRIPTION headline-node)
                              "I learned something neat, and wanted to share!"))
             ;; image: explicit :IMAGE: property wins; otherwise derive from tags
             (image (or (org-element-property :IMAGE headline-node)
                        (blog--image-for-tags heading-tags)))
             ;; tags: merge :TAGS: property with heading tags; strip structural tags
             (structural-tags '("noexport" "draft" "ignore" "details" "details_orange"
                                "details_green" "header" "reexport" "noreexport"))
             (prop-tags  (s-split " " (or (org-element-property :TAGS headline-node) "") t))
             (org-tags   (seq-remove (lambda (tag) (member tag structural-tags)) heading-tags))
             (all-tags   (seq-uniq (append prop-tags org-tags)))
             (tags-str   (s-join " " all-tags))
             ;; abstract
             (abstract (blog--info-subtree-abstract headline-node))
             ;; urls
             (container-base (f-base container-file))
             (url     (blog--url slug))
             (history (blog--history-url container-file)))
        (list (cons "file"        container-base)
              (cons "slug"        slug)
              (cons "container"   container-base)
              (cons "title"       title)
              (cons "date"        date)
              (cons "image"       image)
              (cons "description" description)
              (cons "tags"        tags-str)
              (cons "url"         url)
              (cons "history"     history)
              (cons "abstract"    abstract)
              (cons "draft"       (if draft? "t" nil))
              (cons "redirect"    (org-element-property :REDIRECT headline-node))
              (cons "modified"    (org-element-property :MODIFIED headline-node))
              (cons "site_nav"    (org-element-property :SITE_NAV headline-node)))))))

(defun blog--info-multiple (container-file)
  "Return a list of post-alists for all publishable top-level headings in CONTAINER-FILE.

CONTAINER-FILE must carry #+article_style: multiple.
Headings tagged :noexport: or carrying the COMMENT keyword are excluded.
Headings tagged :draft: are included but marked."
  (with-temp-buffer
    (insert-file-contents container-file)
    (org-mode)
    (let* ((tree (org-element-parse-buffer))
           ;; Collect all level-1 headings
           (top-headings
            (org-element-map tree 'headline
              (lambda (h)
                (when (= (org-element-property :level h) 1) h))))
           ;; A slug is the heading's :CUSTOM_ID:.  Until C-x C-s stamps one, fall back to
           ;; what it will stamp; `blog--validate-slugs' catches any collision.
           (slugs
            (mapcar (lambda (h)
                      (or (org-element-property :CUSTOM_ID h)
                          (blog--make-slug (or (org-element-property :TITLE h)
                                               (org-element-property :raw-value h)))))
                    top-headings)))
      ;; Build alists, skipping noexport/COMMENT headings (blog--info-subtree returns nil for them)
      (delq nil
            (cl-mapcar (lambda (h slug) (blog--info-subtree h container-file slug))
                       top-headings slugs)))))

2.8.12. REDIRECT: zero-duplication bridges to external Org files

Details

Often a project's lovingly maintained README.org, or ~/.emacs.d/init.org, is the article; copying it into a container heading is pointless. Instead, give the heading a :REDIRECT: of a local path or an https:// URL: its body becomes a single #+include: of that file, and Org does the rest. 

* My Literate Emacs Config :emacs:lisp:
:PROPERTIES:
:DATE:        <2024-01-15>
:DESCRIPTION: A literate Emacs configuration, tangled from Org and readable as prose.
:REDIRECT:    ~/.emacs.d/init.org
:END:

* Remote README :docs:
:PROPERTIES:
:DATE:        <2024-02-01>
:REDIRECT:    https://raw.githubusercontent.com/alhassy/example/master/README.org
:END:

The first heading is published with the usual synthetic keywords (#+title:, #+date:, …) followed by 

#+include: "/…/blog/resources/redirects/my-literate-emacs-config.org"

blog--info-subtree carries the "redirect" key along, so the index, tag pages, and RSS treat these articles like any other.

(defun blog--url-p (path)
  "Return non-nil if PATH is an HTTP(S) URL."
  (string-match-p "\\`https?://" path))

(defun blog--already-vendored-p (path)
  "Return non-nil if PATH is already rooted at `blog-redirects-subdir'."
  (string-prefix-p blog-redirects-subdir path))

(defun blog--vendor-one-redirect (slug redirect)
  "Fetch REDIRECT (a local path or http(s) URL) into
`blog-redirects-subdir'/SLUG.org and return the vendored relative path.
A no-op if REDIRECT already points into `blog-redirects-subdir'."
  (if (blog--already-vendored-p redirect)
      redirect
    (let* ((dest-dir (expand-file-name blog-redirects-subdir blog-posts-directory))
           (dest     (expand-file-name (concat slug ".org") dest-dir)))
      (make-directory dest-dir t)
      (cond
       ((blog--url-p redirect)
        (url-copy-file redirect dest t))
       (t
        (let ((src (expand-file-name redirect)))
          (unless (file-exists-p src)
            (user-error "REDIRECT source does not exist: %s" src))
          (copy-file src dest t))))
      (call-process "git" nil nil nil "add" dest)
      (concat blog-redirects-subdir slug ".org"))))

(defun blog--map-publishable-top-headings (fn)
  "Walk top-level headings in the current buffer and call FN with point on each.

Only runs on multiple-style containers.  Skips COMMENTed headings ---the
per-heading FN is responsible for any further filtering (e.g. :noexport:)."
  (when (blog--multiple-style-p)
    (save-excursion
      (goto-char (point-min))
      (while (re-search-forward "^\\* " nil t)
        (unless (org-element-property :commentedp (org-element-at-point))

(defun blog--assign-slugs ()
  "Walk the current buffer's top-level headings; for each without a :CUSTOM_ID:
property, derive one from the heading title (or :TITLE: override) and
write it back via `org-entry-put'.

Called from the C-x C-s preview binding so that, by the time a source
lands in git, every container heading carries a stable :CUSTOM_ID:.  CI then
reads :CUSTOM_ID: and errors out if missing, rather than silently generating
one and writing back to a throwaway checkout."
  (blog--map-publishable-top-headings
   (lambda ()
     (let ((tags (mapcar #'downcase (org-get-tags))))
       (unless (or (member "noexport" tags)
                   (org-entry-get (point) "CUSTOM_ID"))
         (let* ((title (org-get-heading t t t t))
                (slug  (blog--make-slug
                        (or (org-entry-get (point) "TITLE") title))))

(defun blog--vendor-redirects ()
  "Walk the current buffer's top-level headings; for each with a :REDIRECT:
property, vendor the source into `blog-redirects-subdir' and rewrite the
property to the vendored in-repo path.  Only touches multiple-style containers.

Called by `blog-publish-all' (CI) so the rewritten path lands in git and CI
can resolve it on a clean checkout.  NOT called on preview/C-x C-s ---preview
vendors on-the-fly inside `blog--publish-single-subtree' without touching the
source buffer.

Relies on `blog--assign-slugs' having run first so every heading carries
a :CUSTOM_ID: property we can build the vendored filename from."
  (blog--map-publishable-top-headings
   (lambda ()
     (let ((redirect (org-entry-get (point) "REDIRECT"))
           (slug     (org-entry-get (point) "CUSTOM_ID")))
       (when (and redirect slug (not (blog--already-vendored-p redirect)))
         (let ((vendored (blog--vendor-one-redirect slug redirect)))
           (org-entry-put (point) "REDIRECT" vendored)
           (message "=> Vendored redirect for %s ← %s" slug redirect)))))))

2.8.16. RSS feeds: one per tag, plus a global one

Details

RSS, Really Simple Syndication, is a plain-text format a website uses to announce its new content. A reader program —Feedly, Inoreader, Newsboat, NetNewsWire, and dozens of others— subscribes to the URL of a feed and periodically refetches it; when the feed has a new <item>, the reader surfaces it as "there is a new article". The blog does not push; readers pull whenever they want.

So every time we publish, this pipeline regenerates rss.xml; the next time a reader's program polls our URL, it compares entries against what it saw last time and tells the human about any new ones. We never send email, never track subscribers, never even know who is subscribed. Publishing is just "put a new item in the feed"; the rest is the reader's problem.

Why bother at all? Because RSS is the one remaining ambient-notification mechanism for writers on the open web: no algorithm, no platform lock-in, no "follow" button owned by a company. A reader who subscribed in 2008 is still subscribed today, so long as the URL resolves. For a personal technical blog, it is the cheapest way to have an audience that returns.

We emit two flavours of feed:

  • rss.xml —every post, newest first, for the reader who wants everything we write.
  • <tag>-rss.xml —one per tag, e.g., emacs-rss.xml or arabic-rss.xml, for the reader who wants only those articles; each is linked atop its tag page.

Each item carries a <pubDate>, a <link> back to alhassy.com/<slug>, and the article's #+description as its preview text. Bodies are intentionally not embedded: we want readers to click through.

On identity and what counts as “new”. Every <item> also carries a <guid>, a globally unique identifier. Feed readers remember which guids they have already shown their user, and on every refetch compare the feed's current guids against that seen-set:

  • New guid ↦ the reader announces it as a new post.
  • Already-seen guid ↦ the reader ignores the item, even if its title, description, or pubDate changed.

Hence the guid, not the content, decides what our readers hear about. Ours is 

alhassy.com/<slug>?last-updated=<MODIFIED>

or just alhassy.com/<slug> without a :MODIFIED: (#+modified: for standalone posts). Hence an edit re-announces an article exactly when its :MODIFIED: changes.

Partial-commit trick. :MODIFIED: is bumped on every save, and Magit decides the rest: stage its hunk with s to announce the edit, or unstage it with u to ship a typo fix quietly. The “should this notify?” decision lives at commit time, alongside the change. Deriving the date from git log instead would make every [typo] commit re-announce.

3.3.1. Ensuring Useful HTML Anchors

Upon HTML export, each tree heading is assigned an ID to be used for hyperlinks. Default IDs are something like org1957a9d, which does not endure the test of time: Re-export will produce a different id. (defun blog--ensure-useful-section-anchors (&rest _)
  "Org sections without a CUSTOM_ID are given one derived from the heading title.

Uses `blog--make-slug' so the result is lowercase kebab-case, consistent with
URL slugs.  If a collision is detected, pops a message-box and undoes.

E.g., ↯ We'll go on a ∀∃⇅ adventure
   ↦  well-go-on-a-adventure
"
  (interactive)
  (let ((ids))
    (org-map-entries
     (lambda ()
       (org-with-point-at (point)
         (let ((id (org-entry-get nil "CUSTOM_ID")))
           (unless id
             (setq id (blog--make-slug (nth 4 (org-heading-components))))
             (if (not (member id ids))
                 (push id ids)
               (message-box "Oh no, a repeated id!\n\n\t%s" id)
               (undo)
               (setq quit-flag t))
             (org-entry-put nil "CUSTOM_ID" id))))))))

;; Anchor assignment is an interactive-authoring concern ---it should only
;; happen while you can still edit the generated id, i.e. during C-x C-s
;; preview.  CI must not mutate source files, and (undo)/(message-box) don't
;; work headlessly anyway.

4.1. Actually publishing an article

We never publish by hand: we push a .org source to master, and CI runs blog-publish-all, which exports the world into public/ and deploys it to gh-pages; see §4.2.

blog-publish-all dispatches on #+article_style::

  • standalone (the default) —one .org file ↦ one HTML file.
  • multiple ---blog--publish-multiple-articles calls blog--publish-single-subtree on every non-:noexport: top-level heading.

blog--publish-single-subtree turns each heading into a synthetic temp file and exports it just as a standalone article; see §How the export pipeline connects the two styles. 

(cl-defun blog--git (cmd &rest args)
  "Execute git command CMD, which may have %s placeholders whose values are positional in ARGS."
  (let ((default-directory (expand-file-name blog-posts-directory)))
    (shell-command (apply #'format (concat "git " cmd) args))))

(defun blog--multiple-style-p (&optional file)
  "Return non-nil when FILE (or the current buffer) is a multiple-style container."
  (equal "multiple" (if file
                        (blog--article-style file)
                      (blog--file-keyword nil "article_style" "standalone"))))

(defun blog--find-info-by-slug (slug infos)
  "Return the first entry in INFOS whose slug matches SLUG, or nil."
  (seq-find (lambda (a) (equal (@slug a) slug)) infos))

(defun blog--bump-modified-stamp ()
  "Update the MODIFIED timestamp in the current buffer on every C-x C-s.

For standalone-style buffers: rewrites the #+modified: file keyword if
present, or inserts it after #+date: (creating #+date: too if absent).
For multiple-style buffers: sets the :MODIFIED: property on the
top-level heading at point if the property is already present, otherwise
leaves the heading untouched ---absence is intentional (silent edits)."
  (let ((today (format-time-string "%Y-%m-%d")))
    (if (blog--multiple-style-p)
        ;; Multiple style: update :MODIFIED: on the enclosing top-level heading.
        (save-excursion
          (org-back-to-heading t)
          (when (org-entry-get (point) "MODIFIED")
            (org-entry-put (point) "MODIFIED" today)))
      ;; Standalone style: update or insert #+modified: file keyword.
      (save-excursion      
      (save-restriction
        (widen)
        (goto-char (point-min))
        (if (re-search-forward "^#\\+modified:[ ]*.*$" nil t)
            (replace-match (concat "#+modified: " today))
          ;; Insert after #+date: if present, else after the last #+keyword: block.
          (goto-char (point-min))
          (if (re-search-forward "^#\\+date:.*$" nil t)
              (end-of-line)
            (re-search-forward "^#\\+[a-zA-Z].*$" nil t)
            (while (looking-at "\n#\\+[a-zA-Z]")
              (forward-line 1)
              (end-of-line)))
          (insert "\n#+modified: " today)))))))

(defun blog--htmlize-subtree (heading-point slug)
  "Htmlize the subtree at HEADING-POINT in the current buffer to ~/blog/SLUG.org.html.

This produces a per-article colourised source view for container sub-articles.
We copy the subtree content to a temp buffer, narrow to the pasted content,
htmlize, and write the result."
  (save-excursion
    (goto-char heading-point)
    (org-copy-subtree))
  (with-temp-buffer
    (org-mode)
    (org-paste-subtree 1)
    (let ((buffer-file-name (concat slug ".org")))
      (blog--htmlize-to slug))))


(defun blog--publish-single-subtree (heading-point container-file info)
  "Export the subtree at HEADING-POINT in the current buffer to `blog-publish-directory'/SLUG.html.

INFO is the pre-resolved metadata alist for this heading (a single entry
from `blog--info-multiple').  The slug is read from INFO.

The subtree is copied into a temp .org file populated with synthetic
file-level keywords so that the `blog' backend exports it as a standalone article."
  (let* ((slug    (@slug info))
         (tmp-org (make-temp-file "albasmala-" nil ".org"))
         (tmp-buf (find-file-noselect tmp-org)))
    (unwind-protect
        (progn
          ;; 1. Populate temp file with synthetic file-level keywords.
          ;;    blog--info reads these via regex when the `blog' backend calls
          ;;    (blog--info buffer-file-name) during export.
          (with-current-buffer tmp-buf
            (erase-buffer)
            (insert
             "#+title: "                (cdr (assoc "title"       info)) "\n"
             "#+modified: "            (cdr (assoc "date"         info)) "\n"
             "#+fileimage: "           (cdr (assoc "image"        info)) "\n"
             "#+filetags: "            (cdr (assoc "tags"         info)) "\n"
             "#+description: "        (cdr (assoc "description"  info)) "\n"
             (if (equal "t" (cdr (assoc "draft" info))) "#+draft: t\n" "")
             ;; Synthetic overrides ---blog--info prefers these over auto-derived values.
             "#+history_url: "         (cdr (assoc "history"      info)) "\n"
             "#+htmlized_source_url: " (blog--url slug ".org.html") "\n"
             "\n")
            (save-buffer))

          ;; 2. Populate the temp file body.
          ;;
          ;;    When the heading carries a :REDIRECT: property we simply emit a
          ;;    #+include: directive pointing at the external file ---Org's own
          ;;    include machinery handles the rest during export.
          ;;
          ;;    Otherwise we copy the subtree, paste it, axe the redundant
          ;;    top-level heading line, and promote all children one level so
          ;;    blog--style-setup's "^* Abstract" search finds them correctly:
          ;;
          ;;      Before promotion   →   After
          ;;      * Article Title        (deleted)
          ;;      ** Abstract :ignore:   * Abstract :ignore:
          ;;      ** Introduction ...    * Introduction ...
          (let ((redirect (cdr (assoc "redirect" info))))
            (if redirect
                (with-current-buffer tmp-buf
                  (goto-char (point-max))
                  ;; Vendor on-the-fly so the #+include: resolves on this machine
                  ;; and on CI without mutating the source :REDIRECT: property.
                  (insert (format "#+include: \"%s\"\n"
                                  (expand-file-name
                                   (blog--vendor-one-redirect slug redirect)
                                   blog-posts-directory)))
                  (save-buffer))
              (save-excursion
                (goto-char heading-point)
                (org-copy-subtree))
              (with-current-buffer tmp-buf
                (goto-char (point-max))
                (org-paste-subtree 1)
                (goto-char (point-min))
                (when (re-search-forward "^\\* " nil t)
                  (delete-region (line-beginning-position) (line-beginning-position 2)))
                (org-map-entries #'org-promote t)
                (save-buffer))))

          ;; 3. Export with the `blog' backend.
          ;;    Write straight to public/<slug>.html, mirroring the standalone path in
          ;;    `blog-publish-all'; nothing else copies it there, so CI would never deploy it.
          (let* ((html-out (expand-file-name (concat slug ".html") blog-publish-directory)))
            (with-current-buffer tmp-buf
              (let ((blog--link-base-directory (file-name-directory (expand-file-name container-file))))
                (org-export-to-file 'blog html-out))))

          ;; 4. Per-article colourised source: htmlize the subtree narrowed copy.
          (blog--htmlize-subtree heading-point slug))

      ;; Cleanup temp files regardless of errors.
      ;; Mark the buffer unmodified before killing ---this is the only reliable way
      ;; to prevent "Buffer modified, kill anyway?" prompts regardless of what
      ;; kill-buffer-query-functions contains.
      (when (buffer-live-p tmp-buf)
        (with-current-buffer tmp-buf (set-buffer-modified-p nil))
        (kill-buffer tmp-buf))
      (when (file-exists-p tmp-org) (delete-file tmp-org)))))

(defun blog--publish-multiple-articles (container-file)
  "Publish each top-level heading of CONTAINER-FILE as a separate HTML article.

Writes the derived slug back to the heading as a :CUSTOM_ID: property so future
publishes are stable even if the heading title changes.

Returns the list of slugs that were published."
  (let* ((all-infos (blog--info-multiple container-file))
         (by-slug   (let ((h (make-hash-table :test #'equal)))
                      (dolist (i all-infos) (puthash (@slug i) i h))
                      h))
         (results   '()))
    (with-current-buffer (find-file-noselect container-file)
      (save-excursion
        (goto-char (point-min))
        (while (re-search-forward "^\\* " nil t)
          (beginning-of-line)
          (let* ((tags  (mapcar #'downcase (org-get-tags)))
                 (title (org-get-heading t t t t))
                 (slug  (org-entry-get (point) "CUSTOM_ID")))
            (unless (or (member "noexport" tags)
                        (org-element-property :commentedp (org-element-at-point)))
              (unless slug
                (user-error "Container heading %S in %s has no :CUSTOM_ID: property ---run C-x C-s on the source first"
                            title (f-filename container-file)))
              (let ((info (gethash slug by-slug)))
                (message "=> Publishing subtree: %s (%s)..." title slug)
                (blog--publish-single-subtree (point) container-file info)
                (push slug results))))
          (org-end-of-subtree t t))))
    (nreverse results)))

4.2. Deployment via CI

We keep two branches: master holds the sources, and CI owns all the HTML. 

master branch                      gh-pages branch
──────────────────────────────     ─────────────────────────────────
foo.org         (source)      ──►  foo.html     (alhassy.com/foo)
AlBasmala.org   (source)   CI      index.html
resources/                    ──►  tag-emacs.html
AlBasmala.el                       tag-programming-language.html
(NO .html files here)              rss.xml
                                   resources/  ...
  • master holds only sources: .org files, resources/, and config.
  • Every push makes CI export every post, index.html, the tag-*.html pages, and rss.xml into public/, alongside a copy of resources/.
  • peaceiris/actions-gh-pages force-pushes public/ to gh-pages, which GitHub Pages serves at the root; so URLs are flat: alhassy.com/foo.

CI rebuilds everything, every run. A fresh checkout has no public/, so blog-publish-all exports every publishable .org —no mtimes, no diffing— and the deploy overwrites gh-pages wholesale.

Hence a check either runs before any HTML is written, or not at all. blog--validate-slugs runs on C-x C-s, where slug clashes are cheapest to fix, and first thing in blog-publish-all; so a pushed-but-never-previewed edit fails the build rather than silently overwriting one page with another.

  • What is deployed? Browse the gh-pages branch; it is exactly what alhassy.com serves.
  • One-time setup: in the repo's Settings → Pages, set Source to "Deploy from a branch", with branch gh-pages and folder /. Otherwise GitHub Pages serves master, where no HTML lives.
  • Timing: a run takes ~2 minutes, of which exporting is ~30 s; the rest is provisioning a runner and installing Emacs. Public repos get unlimited Actions minutes, so this costs nothing.

4.2.1. Asset sync

Details

HTML refers to assets by relative paths, such as resources/foo.css, which resolve both locally and at alhassy.com/resources/. So blog--sync-assets copies resources/, along with two root-level stragglers, into public/. 

(defun blog--sync-assets ()
  "Copy static assets into blog-publish-directory so relative HTML paths resolve.

Called at the end of `blog-publish-all' so that public/ is self-contained and
can be deployed as-is to gh-pages without the master-branch source tree."
  (let ((dist (file-name-as-directory (expand-file-name blog-publish-directory))))
    (make-directory dist t)
    ;; Required: resources/ must exist ---missing it means a broken site.
    (dolist (asset '("resources"))
      (let ((src (expand-file-name asset blog-posts-directory)))
        (unless (file-exists-p src)
          (user-error "blog--sync-assets: required asset %s missing at %s" asset src))
        (copy-directory src (expand-file-name asset dist) t t t)))
    ;; Optional: nice-to-haves ---silent skip if absent.
    (dolist (asset '("readremaining.js-readremainingjs" "floating-toc.css"))
      (let ((src (expand-file-name asset blog-posts-directory)))
        (when (file-exists-p src)
          (if (file-directory-p src)
              (copy-directory src (expand-file-name asset dist) t t t)
            (copy-file src (expand-file-name asset dist) t)))))))

4.2.2. blog-publish-all: CI entry point

Details

blog-publish-all is what CI calls; locally, it is a full dry-run before pushing. 

(defun blog--publishable-p (file)
  "Return non-nil if FILE is an article that should be published.
A file is publishable when it has any of:
  - #+date:                     ---standalone post
  - #+article_style: multiple   ---container of subtree articles
  - #+site_nav:                 ---top-level nav page (e.g. about.org)

Fragments that are #+include'd into articles but never published on
their own (e.g. MathJaxPreamble.org) must opt out explicitly with

  #+exclude_from_publish: t

Any other .org file missing /both/ a publish marker and the opt-out
signals a (user-error) ---we do not silently skip files that just
forgot their #+date:."
  (with-temp-buffer
    (insert-file-contents file)
    (cl-flet ((kw (k) (blog--file-keyword nil k)))
      (cond
       ((kw "exclude_from_publish") nil)
       ((kw "modified") t)
       ((equal (kw "article_style") "multiple") t)
       ((kw "site_nav") t)
       (t (user-error
           "%s has no #+modified:, #+article_style: multiple, or #+site_nav: ---add one, or #+exclude_from_publish: t if this is an include-only fragment"
           (f-filename file)))))))

(defun blog-publish-all ()
  "Batch-publish every article and regenerate the index.  The sole CI entry point.

Exports all posts → public/, rebuilds index + tag pages + RSS, copies static
assets.  public/ is then deployed by CI to gh-pages so URLs stay flat:
alhassy.com/foo not alhassy.com/public/foo.

Dispatches on #+article_style: per file:
  standalone (default) → one .org → one HTML file,
  multiple            → one subtree → one HTML file (via `blog--publish-multiple-articles')."
  ;; CI passes relative directories, e.g., "./public/"; pin them now, else a nested article's
  ;; buffer would resolve them against its own subdirectory.
  (let ((blog-posts-directory   (expand-file-name blog-posts-directory))
        (blog-publish-directory (file-name-as-directory (expand-file-name blog-publish-directory))))
    (make-directory blog-publish-directory t)
    (blog--refresh-posts)
    (blog--validate-slugs)
    (dolist (f (seq-filter #'blog--publishable-p (blog--org-files)))
      (with-current-buffer (find-file-noselect f)
        ;; badge:/doc:/tweet: links in articles are registered as Org link types
        ;; by org-special-block-extras-mode.  It's a buffer-local minor mode, so
        ;; turn it on per buffer ---without it those links leak verbatim to HTML.
        (org-special-block-extras-mode 1)
        (if (blog--multiple-style-p)
            (progn
              (message "=> Exporting all articles from %s..." (f-base f))
              (blog--vendor-redirects)
              (blog--publish-multiple-articles f))
          (let ((target (expand-file-name (concat (f-base f) ".html") blog-publish-directory)))
            ;; Export directly to public/<base>.html so that #+export_file_name:
            ;; entries pointing at ~/blog/ (valid locally, absent on CI) never
            ;; become the output destination.
            (org-export-to-file 'blog target)))))
    (blog-make-index-page)
    (blog--make-rss-feed)
    (blog--sync-assets)))

(defun blog-insert-image (file)
  "Copy FILE into ~/blog/resources/, git-add it, and insert an Org link, relative to this file, at point.

(defun blog-insert-screenshot ()
  "Take an interactive screenshot, move it to ~/blog/resources/, git-add, insert link.

Uses macOS screencapture -i (crosshair selector).  After the screenshot is taken
you are prompted for a meaningful name; the timestamp default is just a fallback."
  (interactive)

4.2.4. Validation: unique slugs

Details

It enforces §the slug rules on every save and first thing in blog-publish-all. 

(defun blog--validate-slugs ()
  "Signal a `user-error' when a container slug isn't lower-case kebab-case, or two articles share a slug.

Scans blog-posts, which covers both standalone and container articles.  The
effective slug is the :CUSTOM_ID: (container subtrees) or the file basename
(standalone articles); both land at the same URL, so both must be globally
unique.  Only :CUSTOM_ID: slugs must be kebab-case: a standalone basename
like =PathCat= is a long-published URL."
  (let ((seen (make-hash-table :test #'equal)))
    (dolist (p blog-posts)
      (let* ((slug   (or (@slug p) (@file p)))  ; effective URL slug
             (source (format "\"%s\" (%s)"
                             (or (map-elt p "title") slug)
                             (or (map-elt p "source") slug)))
             (prior  (gethash slug seen)))
        (when (and (@slug p) (not (equal slug (blog--make-slug slug))))
          (user-error "Slug \"%s\" of %s isn't lower-case kebab-case; use :CUSTOM_ID: %s"
                      slug source (blog--make-slug slug)))
        (when prior
          ;; Subdirectories don't reach the flat site: emacs/foo.org and life/foo.org both claim foo.html.
          (user-error "Duplicate slug \"%s\":\n  already claimed by %s\n  also claimed by %s\n  %s"
                      slug prior source
                      (if (@slug p) "Change one of the :CUSTOM_ID: properties."
                        "Rename one of the files; subdirectories don't count, the site is flat.")))
        (puthash slug source seen)))))

4.2.5. CI workflow: .github/workflows/ci.yml

Details

This block is the workflow: it tangles to .github/workflows/ci.yml, so any CI workaround sits beside its explanation. One build job

  2. tangles this file and loads AlBasmala.el;
  3. runs blog-publish-all; and
  4. on pushes to master, force-pushes public/ to gh-pages.

    branches: [ master ]
  pull_request:
    branches: [ master ]
  workflow_dispatch:

  group: pages
  cancel-in-progress: false

Appendix 𝐈 Using a Custom Domain: alhassy.com

Details
  1. Go to your repo: https://github.com/alhassy/alhassy.github.io/settings/pages
  2. Add a Custom Domain such as an "apex domain" like alhassy.com (or a www domain like www.alhassy.com)
    • Apex domains require A records to be setup on your DNS provider.
    • www domains require CNAME records.
    • On my DNS provider, I setup both: That way, with or without www., people will arrive at my blog.

  3. Go to your DNS provider, and add two records

    Type Name Priority Content TTL
    CNAME www 0 alhassy.github.io 14400
    CNAME @ 0 alhassy.github.io 14400
  4. In a terminal, run: dig www.alhassy.com +nostats +nocomments +nocmd
    • The www. is intentional.

  5. You should see something like: 

    www.alhassy.com.	14400	IN	CNAME	alhassy.github.io.
alhassy.github.io.	3600	IN	A	185.199.111.153
alhassy.github.io.	3600	IN	A	185.199.108.153
alhassy.github.io.	3600	IN	A	185.199.109.153
alhassy.github.io.	3600	IN	A	185.199.110.153

    This says that it may take 3600 seconds, or 1hour, for the redirect of alhassy.com to alhassy.github.io to be completed. It may take longer; keep reading.

  6. In your DNS provider, add 4 records, one for each IP Address you got from the dig command. (These addresses are also on the official Github docs).

    Type Name Priority Content TTL
    A @ 0 185.199.108.153 14400
    A @ 0 185.199.109.153 14400
    A @ 0 185.199.110.153 14400
    A @ 0 185.199.111.153 14400
  7. Run dig alhassy.com +noall +answer -t A and ensure it points to these IP addresses.
    • Notice the lack of a www.

  8. Open an incognito browser, private browsing session, and navigate to alhassy.com. a. If this redirects to your alhassy.github.io blog, then joy!

    • If the redirect does not happen in your non-incognito browser, just clear your browsing history and try again.

    b. Otherwise, it may take some time (something like 1/2hour to 3 days) for the DNS propagation to be completed.

    • You can check the progress by using a service like this.
    • It took me about 1/2hour for the URL to redirect to my github.io blog.
