﴾How It’s Implemented﴿ 
(org-defblock box (&optional (title "") &key background-color shadow frame-color title-background-color
                  &allow-other-keys :latex-head ("xcolor" "tcolorbox") :manual "#Boxed-Text"
                  &context backend raw-contents contents)
              "Enclose text in a box, possibly with a TITLE.

By default, the box's BACKGROUND-COLOR is green for HTML and red for LaTeX;
for LaTeX, there are also FRAME-COLOR and TITLE-BACKGROUND-COLOR.

SHADOW is an alternate style of boxing: It shows the contents in a centred
box with a shadow colour being the given non-nil value of SHADOW.
If SHADOW is a hexadecimal colour, it should be a string enclosed in double quotes.
More accurately, the following are all valid uses:

    #+begin_box title :shadow t
    #+begin_box title :shadow inset

    #+begin_box title :shadow \"pink\"
    #+begin_box title :shadow pink

    #+begin_box title :shadow (cyan pink orange yellow)
    #+begin_box title :shadow (cyan \"inset pink\" orange)
    #+begin_box title :shadow (:left cyan :right pink :deep-right orange :deep-left yellow)

Notice that prefixing colours with ‘inset’ causes the colour to be within the box,
rather than spread, with blur, around the box. The use of ‘inset’ swaps left and right.

The HTML export uses a padded div, whereas the LaTeX export
requires the tcolorbox package; Markdown, sans colours, gets a quote opening with TITLE in bold."
              (pcase (if (org-export-markdown-p) 'md backend)
                ('md (org-parse (format "#+begin_quote\n%s%s\n#+end_quote"
                                        (if (org-string-nw-p (format "%s" title)) (format "*%s*\n\n" title) "")
                                        raw-contents)))
                ;; Colours are named first, since tcolorbox options cannot take hex codes such as #CCFFCC.
                ('latex
                 (concat (org--latex-define-color "osbe-box-back" (or background-color "red!5!white"))

                         (format (concat "\\begin{tcolorbox}[title={%s},colback=osbe-box-back,colframe=osbe-box-frame,"

                                         "subtitle style={boxrule=0.4pt, colback=yellow!50!red!25!white}]"

                (_ (format "<div style=\"%s\"> <h3>%s</h3> %s </div>"

                                             (format "background-color: %s" (org-subtle-colors (format "%s" (or background-color "green"))))

2. Folded Details —Let the user see stuff only if they're interested

﴾What You Write﴿ 
Sometimes there is a remark or a code snippet that is useful to
have, but not relevant to the discussion at hand and so we want to
/fold away such [[doc:org-block/details][details]]/.

+ ‘Conversation-style’ articles, where the author asks the reader questions

#+end_details

Full syntax ~#+begin_details "title" :background-color "cyan" :title-color "green"~.

Src blocks fold too: the header argument :folded t exports a src block, exactly as Org otherwise would, inside a details block titled by its language; :folded "TITLE" picks the title. 

#+begin_src emacs-lisp :folded "How is it done?"
(org-defblock details …)
#+end_src

A page with many folded blocks may offer a button to unfold them all at once: [[toggle-details:][Show me everything]] is that button; pressed again, it folds them all. Without a description, it reads “Unfold all details”.

3. Nice Keystroke Renditions: C-h t

Anyone who writes about Emacs will likely want to mention keystrokes in an aesthetically pleasing way, such as C-u 80 - to insert 80 dashes, or C-c C-e h o to export an Org-mode file to HTML, or the useful M-s h ..

  • kbd:𝒳 will show a tooltip defining 𝒳, as an Emacs Lisp function, if possible. For example, kbd:C-h_t is C-h t; and likewise <kbd:M-s h .> is M-s h. (we need to use <...> since punctuation is not picked up as part of link labels). In contrast, kbd:nope renders as nope without a tooltip (nor a red border).

    You can also supply explicit tooltip description: [[kbd:key sequence][description]] will show as key sequence; i.e., the key sequence in nice key font along with a tooltip explaining it.

  • In Emacs itself, each of these displays as 〔C-x C-s〕: the kbd: markup becomes the brackets and each _ a space. Only the markup is displayed differently, so the keys stay editable as ever. Moreover, clicking one runs its keys —after asking, as elisp: links do— so readers may try them on the spot.

4. Remark —Inline footnotes, viz HTML tooltips and LaTeX notes in the margin

Sometimes you want to remark on details without drawing too much attention, and so a tooltip via remark suffices.

﴾What You Write﴿ 
It can be annoying to make readers jump to the bottom of the page to
read a footnote.  Instead, I prefer to write an /inline [[doc:org-block/tooltip][remark]]/
containing, say, references or additional explanation.

   /[[tooltip:Allah][The God of Abraham; known as Elohim in the Bible]] does not burden a
       soul beyond what it can bear./ --- Quran 2:286

Or, without specifying an explicit label:

   /Allah[[tooltip:][The God of Abraham; known as Elohim in the Bible]] does not
       burden a soul beyond what it can bear./ --- Quran 2:286
﴾What You Get﴿

It can be annoying to make readers jump to the bottom of the page to read a footnote. Instead, I prefer to write an inline remark containing, say, references or additional explanation.

Allah  does not burden a soul beyond what it can bear. — Quran 2:286

Or, without specifying an explicit label:

A tooltip opens when its word is hovered with a mouse, or tapped on a phone; it closes when we leave both, tap elsewhere, or press Escape. Its text is Org, exported as Org, so it may hold links —clickable, since moving into the tooltip keeps it open— and any other markup; an Elisp docstring is shown just as it is written. The machinery is tooltips.js, about eighty lines with no dependencies, in the look of tooltips.css; both are inlined into each exported page, which so fetches nothing for them.

Org's own footnotes are such remarks too: in HTML, each footnote's number is a tooltip of its definition, the footnotes section staying below, for print; in LaTeX, each is a margin note, as the margin block's are, numbered as footnotes are. All three of Org's spellings serve: an anonymous [fn::…], a named [fn:NAME] defined elsewhere, and a named inline [fn:NAME: …], which later [fn:NAME] references share.

Torah[fn:-0-torah] and the Gospel[fn:-0-injil: /Injil/, given to Jesus.] are honoured in it as earlier
scriptures; the Gospel[fn:-0-injil] is named in it a dozen times.

[fn:-0-torah] /Tawrat/, given to Moses; see [[https://en.wikipedia.org/wiki/Tawrat][Tawrat]].

5. Glossaries —Define a term once, cite it with doc:𝒳

A doc:𝒳 link shows the documentation of 𝒳 as a tooltip in HTML, and as a glossary reference in LaTeX. Here 𝒳 is an Emacs Lisp function or variable, a word in the English dictionary —via WordNet's wn, should we have it— or, best of all, a term of our own.

﴾What You Write﴿ 
The ~doc~ link type can be used to show tooltips for Emacs Lisp commands such as

                         doc:thread-last
                         
However, it can also be used for your own definitions/glossary.
First define a term as follows, which does not render anything in the resulting HTML.

                 #+begin_documentation Category Theory :label cat
                 A theory of typed composition; e.g., typed monoids.
                 #+end_documentation

Then you can refer to it using the given :label, if any:

                             doc:cat
  
Or else refer to it with underscores in lieu of spaces:

                       doc:Category_Theory

Either approach renders the name of the term, not the way its referenced.
If you want to change what's rendered, provide a description:

                  [[doc:cat][abstract nonsense]]

Finally, if ~doc~ gets a label that is not an Emacs Lisp command, variable, nor a user-defined
definition via #+begin_documentation, then we try to look up its definition via the dictionary:

                          doc:happiness

﴾How It’s Implemented﴿ 
(org-deflink doc (label &optional description backend)
  "Export LABEL as itself, or as the provided DESCRIPTION,
 along with a tooltip that shows the user's
 documentation-glossary for LABEL and using that entry's name
 when no DESCRIPTION is provided."
  :let (entry (org-docs-get label)
        name (cl-first entry)
        docs (cl-second entry)
        display-name (or description name))
  :help-echo (format "[%s] %s :: %s" label name docs)
  :face '(custom-button)
  :manual "#Glossaries"
  :export (progn
            (add-to-list 'org--docs-actually-used (list label name docs))
            (pcase backend
              ('html (org--html-tooltip docs display-name (org--docs-plain-p label)))
              ;; Make the current word refer to its glossary entry, and declare the location
              ;; that the glossary should refer back to; see `org--docs-glossary'.
              ('latex (format "\\hyperref[o-glossary-%s]{%s}\\label{o-glossary-declaration-site-%s}"
                              label display-name label))
              (_ display-name))))

Our own terms are data in an Org file: an entry is either a documentation block, which exports nothing, or a heading tagged :documentation:, which exports as an ordinary section. The heading's title is the term's name, its :DOC_KEYS: property lists the labels by which we cite it, and its own text is the definition. Either way, the name with underscores in lieu of spaces is a label too; e.g., doc:Category_Theory. Moreover, as #+print_bibliography: lists the works a page cites, #+print_glossary: lists every term the page cites, wherever it sits.

Org's own radio targets are entries too, with no markup of ours at all: in “A <<<monoid>>> is a unital semigroup”, Org already links each later “monoid” to its definition; in HTML, each such mention is also a tooltip of the defining paragraph.

Terms we cite across many files go in a library: a list of Org files in org-docs-libraries, whose entries —blocks and headings alike— every doc:𝒳 link may cite. The files are read, not exported, so loading them is quick; M-x org-docs-load-libraries reloads them after an edit, and M-x org-docs-insert inserts a doc:𝒳 link by searching all the terms we have.

A radio target is a term too: in A <<<monoid>>> is a set with an associative operation and a unit., the target names the term and its paragraph defines it; so doc:monoid cites it, in the same file or, from a library, in any other.

7. Display maths ---#+begin_math, wherein red:𝒳 colours a symbol

To colour a formula, LaTeX —and MathJax, which typesets it in HTML— would have us write {\color{red} x}; yet our prose colours by red:x. A math block is display maths wherein our links are LaTeX's: red:ATOM colours a {group}, \left(…\right), a \command{with}{arguments}, a word, else one character; [[red:][a + b]] colours a + b. So too for color:#ff0066, highlight:, web links, and tooltip: and doc:, which hover in HTML; as does a footnote, x[fn::the current element], or x[fn:elt], whose [fn:elt] … definition sits elsewhere, as in prose —so one long tip serves many atoms. A tooltip in maths is as one in prose: the same box in HTML, and in LaTeX, a margin note, its number on x. Org's emphasis is read when its markers hug their text, as in prose: *f(a)* is bold, whereas a*b*c and a = b are left be.

A line that begins \def, \newcommand, …, begins a definition, through the line that closes its braces: declared, but not shown —in LaTeX, in the preamble; in HTML, hidden, whence MathJax knows it page-wide. A line # … is a comment. Below, the first block is only definitions, and so shows nothing.

﴾What You Write﴿ 
Hello, in this blog post I'd like to talk about quantifiers.

# First, I'll define some helpers that I use multiple times; they are declared, not shown.
#+begin_math
\def\Plus{teal:\bigoplus}
\def\plus{\;teal:\oplus\;}
\def\f#1{brown:f violet:{(#1)}}
\def\xstart{red:a}
\def\xend{cyan:b}
#+end_math

Anyhow, let's talk about quantifiers...
#+begin_math

8. Aligned equations ---& in a math block, cited by [[𝒳]]

A math block whose lines have an & is LaTeX's align: its lines line up at each &. As in LaTeX, a line ends in \\, unless it ends in a tag COLOUR:<<NAME>>, which is NAME in that colour, as red:x colours maths; <<NAME>> is plain. It is Org's own target, so NAME may hold spaces, and a _ is a subscript: <<Base Case_1>> is tagged “Base Case₁”. Its brackets delimit it, so a hint's nested calculation, \[ … \], may hold one too. We cite it as Org cites any named thing: [[NAME]] is its number, or name, as LaTeX's \eqref shows it; and [[NAME][these words]] links the words to it. C-c C-o on the link, in Emacs, visits the line; failing that, any \tag{…NAME…}. A NAME may hold maths, such as ⊑-Definition or Distributivity of \meet, which shows as maths in the tag, and is cited by the very same name. With :numbered t, the untagged lines are numbered too. 9. Calculational proofs ---REL{ HINT } in a math block, folded by TAB

A calculational proof states why each step holds. We write the hint right after the relation, X ={ HINT } Y, and it shows on a row of its own, between the two expressions it relates —as Feijen and Dijkstra set a calculation— in maroon, after a bracket that opens it, lest it be mistaken for maths. So too for any relation ---≤{ … }, \equiv{ … }, or a :let shorthand's. The { hugs the relation and a space or newline follows it, so LaTeX's own x ={a} and \frac{ a }{ b } are left be. So that we need not recall the rule, Emacs shows each hint as a comment, by the very reading the export makes; any other {…} is LaTeX's own.

A step runs from its hint to the next, wherever the newlines fall —we need not write \\, and may give each expression and hint a line of its own, in Dijkstra's style, or not. 

#+begin_math :let (== "\\equiv")
p \land q =={ Golden Rule } p == q == p \lor q
           =={ by symmetry } q \land p
#+end_math

A hint may span lines, as a long reason does, and shows on those very lines —a blank one a gap between paragraphs. Within a hint, \[ … \] is a nested calculation, whose own hints are read alike, so they may nest in turn; one sans hints is a mere displayed formula.

  • TAB on a hint folds it away to {…}, and TAB again unfolds it —the proof's outline at a glance; so too in the block's C-c ' buffer. C-TAB within a block folds all its hints, unless all are folded, whence it unfolds them. In HTML, a click on a hint folds it, and a shift-click all hints of its proof, as its tooltip says. With point on a hint, the echo area says what it is, how to write it, and how to fold it.
  • M-q within a hint fills the paragraph at point alone, as prose, and so sets its lines; M-q elsewhere in the block, or within a nested calculation, leaves the maths be.
  • A line # … is a comment, even within a hint: say, an alternative reason, kept in the source yet absent from the export.

  • :hints says how hints show:

    :hints between On a row of their own, maroon and bracketed: the default.
    :hints beside At their step's end, plain, as their column sets them apart.
    :hints none Hidden from the export; the steps remain, a compact chain.
    :hints (beside "{\color{teal} \langle %s \rangle}") A layout, then a format of our own, LaTeX whose %s is the hint.
    :hints (between folded) Folded, so a page's reader clicks to see each —a puzzle!

    A format may join folded, as in (between "{\color{teal} %s}" folded). LaTeX, sans clicks, shows folded hints in full. Hints beside read well when the expressions are narrow; to have them so throughout a file, we say it once, as for any block's header arguments:

Euler's Handshaking Lemma

At a party of 7 people, is it possible that everybody knows exactly 3 other people?

We could consider all possible cases, which is not particularly enlightening; or we could calculate…

\[\def\even#1{\mathsf{even}\,\left(#1\right)} \def\odd#1{\mathsf{odd}\,\left(#1\right)}\]

\begin{align*} & \begin{array}{l} \text{“Obviously”, the sum of everyone's friendship count} \\ \text{is twice the total number of friendships} \end{array} \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \begin{array}{@{}l@{}} \text{Formalise...} \\ \\ \text{Let $f(p)$ denote the number of friends that person $p$} \\ \text{has, which is 0 if $p$ has no friends.} \\ \\ \text{Let $F$ be the total number of friendships (between any 2 people).} \\ \\ \text{Since friendships are always between two people, we have} \\ \text{that $\sum_p f(p) = 2 × F$: Counting-up the number of} \\ \text{friends that everyone has will always be twice the total} \\ \text{number of relationships ---which is always an even number.} \\ \\ \text{Formally,} \\ \begin{aligned}[t] & \text{sum of everyone's friendship count} \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{Formalise, where $p$ ranges over people} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \\ & \sum_p f(p) \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \begin{array}{@{}l@{}} \text{Definition of $f$: Let $𝑭𝒓_{p, r}$ be 1 exactly when $p$} \\ \text{participates in friendship/relationship $r$, and 0} \\ \text{otherwise, then $f(p) = \sum_r 𝑭𝒓_{p, r}$.} \end{array} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \\ & \sum_p \sum_r 𝑭𝒓_{p, r} \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{Quantifier interchange; i.e., Fubini's Principle} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \\ & \sum_r \sum_p 𝑭𝒓_{p, r} \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \begin{array}{@{}l@{}} \text{Every relationship $r$ is between 2 people;} \\ \text{i.e., $\sum_p 𝑭𝒓_{p, r} = 2$} \end{array} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \\ & \sum_r 2 \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{Factoring} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \\ & 2 × \sum_r 1 \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{The total number of friendships is $F$} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \\ & 2 × F \end{aligned} \end{array} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \notag \\ & ∑_p f(p) = 2×F \\ ⇒ & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \begin{array}{@{}l@{}} \text{Equals for equals; (‘true’ is the identity of ‘$≡$’)} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \notag \\ & \even{∑_p f(p)} \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{$\even{-}$ distributes over sums turning them into equivalences ‘$≡$’} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \notag \\ & {\LARGE ≡}_p \;\even{f(p)} \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \begin{array}{@{}l@{}} \text{By definition, a chain of equivalences is true exactly when} \\ \text{it has an even number of false values} \end{array} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \notag \\ & \even{ ♯\{p ∣ ¬ \even{f(p)}\} } \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{A non-even number is precisely an odd number} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \notag \\ & \even{ ♯\{p ∣ \odd{f(p)} \} } \\ = & \quad \class{tooltip osbe-tip-hint osbe-hint}{\class{osbe-hint-body}{{\color[RGB]{128,0,0} \left[ \text{Un-formalise} \right.}}\class{osbe-hint-fold}{{\color[RGB]{128,0,0} [\,\cdots\,]}}} \notag \\ & \text{an even number of people have an odd number of friends} \end{align*}

Back to the problem: At a party of 7 people, is it possible that everybody knows exactly 3 other people?

If such a party were possible, the number of people with an odd friend count must be even, but 7 is not even, and so no such party is possible. ( Alternatively, if such a party were possible, then by the Handshaking Lemma, \(F = {∑_p f(p) \over 2} = {7 × 3 \over 2} = 10.5\): This is absurd since there cannot be a ‘.5’ relationship! Hence, no such party is possible. )

So a demo is three things at once:

  1. A demonstration, in the docs: the source, then its rendering; the snapshot is what is shown, so a reader sees what we saw, whatever build of ours renders the page.
  2. A test in the small, upon export: the block is rendered afresh and compared, sans whitespace and case, to its snapshot; a mismatch is a warning, or an error, or nothing, as org-demo-check says. The hash, [96978da579], tells the two failures apart: a source changed since its snapshot, or a rendering that changed for the same source —a regression, or an intended change, which another C-c C-c records.

  3. A test suite in the large: org-demo-failures checks every demo of a file, along every snapshotted backend; this manual's own are an ERT test, 

    (ert-deftest manual ()
  (should-not (org-demo-failures "org-special-block-extras.org")))

M-x org-demo-refresh-buffer snapshots them all; C-u C-c C-c leaves C-c C-c to the block's own action, if any.

A demo's value says what else to show: :demo org-block/box folds away the definition of org-block/box, below the rendering; :demo (f v) those of the function f and the variable v, wherever they are defined —a library, or this very document. A live demo, :demo live, keeps no snapshot: its rendering varies by machine, say, so it renders afresh each export and checks nothing; so C-c C-c in it is the block's own, such as a graph's.

Its other switches apply as ever: :let to its source, :folded to the whole showing. With :ignore t, the block is bypassed, so the source is just its contents —the way to demonstrate plain Org, or several blocks at once; as in an example block, a line opening with * or #+ may be escaped by a comma, so a demo may hold headings.

Set theory is that branch of mathematics whose task is to investigate

In LaTeX, and so in beamer, this is csquotes' \blockcquote[20-22]{zermelo1908}{…}, cited by our bibliography —biblatex's \addbibresource, BibTeX's \bibliography, or org-cite— which is ours to give; csquotes itself is loaded for us, unless we load it ourselves. 17. Markdown export —What survives GitHub, and how to change it
